<a id="control-adapter-contract"></a>
# 控制适配器契约

Benny 并不知道如何启动或操作每一种应用。用户必须为目标应用配置一个实现此契约的控制技能或适配器。

在 `control.skill_name` 中设置其技能名。

在 `control.feature_map_path` 中设置已完成的、面向用户的功能映射路径。将 [`feature-map.example.md`](./feature-map.example.md) 复制到 `.cursor/automations/benny/` 之外并填写，不要编辑复制包中的示例。

如果技能、功能映射或某项必需能力缺失、含糊或不完整，复现与修复工作必须以关闭方式失败。

<a id="required-capabilities"></a>
## 必需能力

<a id="bring-up"></a>
### 启动

在请求的测试环境中启动请求的应用版本。

输入：

- 仓库和修订版本
- 构建或启动模式
- 工作区、账号、测试夹具和功能状态要求
- 产物目录
- 已完成的功能映射路径

返回：

- 会话标识符
- 适配器如何确认应用和环境正确
- 稳定的应用标记
- 后续调用需要的运行进程或目标详情
- 任何缺失能力

适配器必须区分目标应用与相似窗口、shell 或生产实例。

<a id="drive-ui"></a>
### 操作 UI

执行真实用户操作：

- 点击
- 输入
- 按键
- 滚动
- 拖动
- 调整大小
- 通过应用控件导航

优先使用角色、标签和稳定选择器。只有获得新截图后才使用坐标。

返回每个操作及观察到的状态变化。

不要设置内部状态、调用隐藏应用方法、直接写入存储或注入 DOM 改动来制造症状。

<a id="drive-mapped-features-and-states"></a>
### 操作映射的功能和状态

操作应用前，读取相关功能映射章节。

适配器必须提供以下方式：

- 通过用户可见的路径导航到每个映射功能。
- 调用该功能列出的适配器操作名。
- 在适用时，操作 default（默认）、hover（悬停）、focus-visible（焦点可见）、active（激活）、disabled（禁用）、loading（加载中）、empty（空）、error（错误）、selected（已选）、open（打开）、expanded（展开）及功能特有的状态。
- 通过安全的测试夹具数据、权限、标志、服务响应或受支持的测试控件准备状态。
- 重置功能，以便进行第二次独立复现尝试。
- 采集功能映射指定的截图、视频和只读交叉核验。

使用角色、无障碍名称、ARIA 关系、稳定的组件标记和按用途命名的数据属性。绝不使用生成的 CSS 或 StyleX 类、动态哈希、子元素索引或脆弱的 DOM 位置。

准备前置条件不代表获准注入报告的症状。复现本身仍必须来自真实用户交互。

<a id="inspect-state"></a>
### 检查状态

读取状态以确认 UI 所显示的内容。

例如：

- 无障碍树
- DOM 或视图层级
- 进程状态
- 本地日志
- 网络请求状态
- 应用暴露的调试状态

检查是只读的。如果查询会改变状态，它就属于 `drive UI`，并且必须代表真实用户操作。

<a id="screenshot"></a>
### 截图

将当前应用状态截图保存到请求的路径。

返回：

- 文件路径
- 采集时间
- 应用标记或窗口标题
- 对应当可见内容的简短描述

截图必须展示足够的应用界面框架，以证明正在测试正确的应用。

<a id="recording"></a>
### 录屏

围绕完整复现路径开始和停止屏幕录制。

返回：

- 文件路径
- 开始和停止时间
- 录制的窗口或区域
- 是否省略音频或敏感覆盖层

录屏必须展示能区分该问题的最终状态，不能仅展示设置或加载画面。

<a id="cleanup"></a>
### 清理

停止适配器创建的进程和会话。

移除可丢弃的：

- 浏览器或应用配置文件
- 临时工作区
- 由适配器创建的测试账号或测试夹具
- 调试端口和隧道
- 超过保留窗口的采集文件

返回已停止、移除、保留或留待人工处理的内容。

清理绝不能删除用户工作。

<a id="adapter-behavior"></a>
## 适配器行为

适配器必须：

- 复现开始前报告能力。
- 报告它可以操作哪些功能映射章节，以及哪些受阻。
- 基线构建和打补丁的构建使用相同的环境输入。
- 如实将启动失败报告为失败。
- 限制重试。
- 防止秘密信息进入日志和产物。
- 将采集文件保存在仓库之外。
- 在两次复现尝试之间支持全新或重置后的状态。
- 除非用户明确配置了安全测试操作，否则避免生产环境变更。

<a id="environment-translation"></a>
## 环境等效转换

宣告环境阻塞前，去掉平台专属名词重新描述缺陷，并判断能否在现有环境中安全测试相同行为。

例如：

- 指定的浏览器可能可以换成任意外部浏览器。
- 指定的按键可能实际指配置的快捷键。
- 指定的远程主机可能实际指延迟或断开的远程目标。

只有测试的是相同底层行为时，才使用等效转换后的尝试。将其标为经过等效转换的证据。如果缺失环境本身是缺陷的一部分，不要称之为精确复现。

硬件提示、操作系统权限对话框、仅设备可用的 API 和不可用的账号状态，都可能是真实阻塞。

<a id="setup-check"></a>
## 设置检查

启用复现自动化前，运行一次无害的适配器检查：

1. 启动应用。
2. 确认稳定的应用标记。
3. 加载一个已完成的功能映射章节。
4. 通过其用户路径导航到该功能。
5. 通过映射的适配器操作，操作一个可丢弃的状态。
6. 检查结果状态。
7. 采集截图。
8. 录制短片。
9. 清理。

只有九个步骤全部成功，且没有在来源频道发送 Slack 消息时，才能启用复现工作。
