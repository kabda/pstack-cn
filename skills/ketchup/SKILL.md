<a id="ketchup"></a>

# 进展简报

向用户说明他们在 `/ketchup` 之前最后一条消息以来，本聊天发生的变化；帮助他们理解每项变化，而不只是知道状态。随后列出等待他们决策的所有事项，让他们只看回复就能决定。通知和子代理结果不算用户消息。假定用户只记得自己的上一条消息，不知道之后的内容。

采用 [`/bro`](../bro/SKILL.md) 的语气，而非其任务：平实词语、短句、无术语，就像一个人给另一个人补充近况。说明用户得到什么变化，不说你怎样完成。说“测试通过”，不说“CI 全绿”。除非用户需要据此行动，否则不写哈希、文件路径、命令、构建号和测试数量。用用户能识别的名字称呼 PR、分支或智能体，不用自创标签。某个事实需要背景才能理解，就补背景，否则删掉。

<a id="gather-what-changed"></a>

## 收集变化

本回合保持只读。只用已有材料制作图示：不改代码、不启动应用或任务、不发布内容。收集自那条消息以来你自己的工作、子代理报告和聊天中其他人的消息。检查本聊天触及的每个 PR、CI 运行或智能体当前状态。每个要展示的数字都核对其事实来源；纠正数字时说明。

待办事项只能是用户才能作出的决定或步骤，例如产品选择、批准、不可逆操作，或你缺少的访问权限。所有仍等用户的事项都要纳入，即使在上一条消息之前就提出。你仍能自行完成的工作不算待办。绝不为凑回复虚构决策。用户未要求、工作也不需要的步骤不算待办，除非它不可逆且正在等待用户；这种情况只写一行，不画图。

一个决策可能覆盖多项，例如一组待合并 PR。为每项收集链接、对用户的变化、支持建议的证据、风险，以及你的建议。决策所需事实不知道就写“未知”，没有的链接不要写。

<a id="write-the-reply"></a>

## 撰写回复

把文字花在决策上，而非过程故事。发生经过保持在 100 词以内，不算图片；事情少时更短。对用户没有产生变化的工作不写。每个事项约 30 词。回复随事项数量增长：两项合计应远低于 150 词，不算图片；30 项则需要多得多的文字。绝不能为满足字数削减事项或缩短到不完整：不能用总数代替清单，也不能用链接代替事项。链接可以补深度，但只看回复本身就必须足以决定。

开头用一个短句说明在等用户什么，或没有事项等待。细节由待办部分给出。如果什么都没发生、也没事项等待，说明后停止。

接着展示发生了什么，先放图片。内联嵌入工作产生的截图和视频，再放解释变化的图示。随后，针对用户要求的每件事各用一个短列表项总结：结果是什么，是完成、仍在运行、失败，还是未检查。每行像口头表达：“缺少索引导致搜索缓慢”，不要写“搜索审查：完成”或“慢搜索：缺少索引”。指出过程中发现并修复的缺陷。每行单独阅读也必须真实。仍待用户处理的事绝不标成完成；待办部分已说明的内容不要重复。总结后最多给三条短句，只写会改变用户认知或行动的内容。再用一行说明你仍可自行完成的剩余工作。

随后列待办事项。询问属于用户的决定，例如合并、批准或选择，并给出建议。你会先采取的步骤、任何前置事项、不可撤销事项，都放在建议中。每个决策涉及的 PR、issue 或智能体都给编号或链接，选项间决策也一样。

根据决策类型组织。针对单项的决策用一个列表项：决策、建议、用户变化、建议证据、风险；该事项只点名一次。多个事项共享同一决策时，决策和建议只写一次，然后每项单独一个列表项，风险最高的先写：链接与名称、用户变化、建议证据、风险。只有某项建议与总建议不同才单独注明。即使风险低，也给出每项风险，例如“风险低：只改变颜色”。只有等待代价超过单纯延迟时才说明，例如错过截止时间或丢失数据。

选项间决策，列出工作中权衡过的所有选项，各自说明用户收益、代价，以及存在时的当前状态。这些代价就是决策风险，不再单列风险行。上方截图已展示选项时，把每个选项的收益与代价写在对应截图下面。

<a id="visuals"></a>

## 图示

图示是图片：截图、视频、Mermaid 图、`/visualize`（Cursor）或运行环境图表工具生成的图表，或生成图像。Markdown 表格不是图示，即使有改动前后列。

某件事用图比句子更容易理解时，就画：设计或系统原理、带每个 PR 状态的 PR 堆栈或依赖链、修复前后对比，或并列选项。绝不画状态列表、待办列表，或彼此没有连线的盒子。任何事实都不重复，无论文字还是不同图示之间。

每幅图要小到一眼能读懂：最多六个框，每框最多八个词。标签用人会说的平实语言，不用“测试：通过”之类标签。需要一句话才能讲明的事实，放在文字里，否则不写。

可见变化的截图和视频要内联嵌入，不只给链接。如果可见变化没有截图，在总结对应行标注“尚无截图”，并说明屏幕上变了什么。图示和图表必须来自已有事实：连接关系用 Mermaid，数字用图表（Cursor 的 `/visualize`，或运行环境的图表工具）。绝不虚构数字，绝不绘制或生成未经捕获的屏幕画面。只链接实际存在的产物。
