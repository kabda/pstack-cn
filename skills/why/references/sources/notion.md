# Notion 文档

<a id="what-this-source-contains"></a>
## 此来源包含什么

- PRD（产品需求文档）
- 技术规格和 RFC
- 架构决策记录（ADR）
- 设计评审的会议记录
- 提供领域背景的团队页面
- 事故复盘
- 可能解释防御性代码的运维手册
- 确定优先级的战略文档

“为什么”常在变成代码之前，以长篇形式存在于 Notion 中。重要功能通常有文档。

<a id="how-to-search-it"></a>
## 如何搜索

使用 Notion MCP。

1. **用 `notion-search` 做关键词搜索。** 尝试：
   - 功能名称
   - 目标代码中的关键符号／类名
   - 作者账号（设计文档常在代码合入前编写）
   - 错误字符串或用户可见术语
   - 已知代码交付时间时，限定时间查询
2. **用 `notion-fetch` 获取候选页面。** 阅读完整内容，而非预览。依据常藏在文档中段。
3. **追踪反向链接和子页面。** 设计文档常有用于备选方案、附录或实现说明的子页面。
4. **检查相关数据库。** `notion-query-data-sources` 和 `notion-query-meeting-notes` 可以发现讨论该决策的会议记录。
5. **搜索作者专属空间。** 如果 PR 作者有个人笔记本（一些公司常见），其中可能记录代码之前的探索思路。

<a id="what-good-evidence-looks-like-here"></a>
## 此处的优质证据

- PRD 的 “Problem statement”（问题陈述）或 “Motivation”（动机）章节与目标代码用途匹配
- “Alternatives considered”（考虑过的备选方案）或 “Rejected approaches”（被否决的方法）章节
- 指出目标代码是某次具体事故修复措施的复盘
- 记录“我们决定 X，因为 Y”，且作者／日期范围与 PR 一致的会议记录
- 有实质内容的 ADR 模板（状态、背景、决策、后果）

<a id="common-pitfalls"></a>
## 常见陷阱

- **过时文档。** 规格常在实现前编写，且未更新。文档可能描述了已变化的计划。与实际 PR 交叉检查。
- **文档与现实漂移。** 规格可能说“我们将做 X”，而代码实际做 Y。标明分歧，由综合者展示矛盾。
- **模板套话。** 某些组织要求 “Why”（为什么）章节，却填入空话。寻找具体内容。
- **未被链接的文档。** 最相关的文档可能没有任何入口链接。广泛的关键词搜索会有帮助。
- **多个草稿。** 同一主题有多份文档时，找到已定稿或最近更新的版本。检查日期。
- **访问受限页面。** 无法访问时，将其记为缺口。

<a id="what-to-return"></a>
## 返回内容

对每个相关文档：
- 标题和 URL
- 作者和最后更新日期
- 动机文本（逐字引用），附页面／章节位置
- 相关链接页面（供综合者引用）
- 文档是定稿还是草稿
