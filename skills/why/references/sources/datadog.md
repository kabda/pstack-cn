# Datadog 遥测

<a id="what-this-source-contains"></a>
## 此来源包含什么

Datadog 保存运行时记录，即生产环境实际发生过什么，而非计划或讨论过什么。

- **指标。** 团队埋点的计数器、仪表、直方图。某指标的*存在*本身就说明有人认为这个数字值得观察。
- **监控与告警。** 团队认为值得唤醒人员的条件。对 `rate_limit_hit > 10/min` 触发告警的监控，是团队关注此阈值的直接证据。
- **仪表盘。** 精选视图，展示团队认为子系统中重要的内容。
- **APM 跟踪与 span。** 请求级运行数据，用于“为什么慢”或“为什么这里超时”等问题。
- **日志。** 大量事件记录，常包含促成防御性代码的错误条件。
- **事故。** 包含时间线和复盘链接的正式事故记录。
- **笔记本。** 团队的探索调查，常有假设和分析。

<a id="how-to-search-it"></a>
## 如何搜索

使用 Datadog MCP。先广后窄。

1. **识别负责的服务。**

   ```
   search_datadog_services（按名称或团队筛选）
   search_datadog_service_dependencies（查看上游／下游）
   ```

2. **先看仪表盘和监控。**

   ```
   search_datadog_dashboards（查询：功能名、服务名、符号）
   search_datadog_monitors（使用相同查询）
   ```

   仪表盘或监控覆盖目标时，记录其查询和观察阈值。阈值往往就是“为什么限制为 N”的答案。

3. **目标周边的指标。**

   ```
   search_datadog_metrics（按名称模式，如功能或符号）
   get_datadog_metric_context（元数据：描述、单位、标签）
   get_datadog_metric（时间序列；“PR 日期前后是否出现峰值？”）
   ```

   将指标轨迹与目标添加／更改日期关联，是有力的支持证据：“`payment_timeout` 指标于 2023-11-03 激增，重试逻辑于 2023-11-06 合并。”

4. **日志：收窄，不倾倒。**

   ```
   search_datadog_logs（目标附近的原始日志模式，设置 use_log_patterns=true）
   analyze_datadog_logs（SQL 风格聚合，仅在需要计数时使用）
   ```

   用符号、错误字符串或功能名搜索。**强烈优先采用有时间边界的查询**（例如改动前后各 30 天）。

5. **APM span 和跟踪。**

   ```
   aggregate_spans（统计：“这个端点失败频率是多少？”）
   search_datadog_spans（检查单个 span）
   get_datadog_trace（特定 trace ID）
   ```

   适用于超时、重试、慢路径和跨服务行为。

6. **事故。**

   ```
   search_datadog_incidents（按标题、团队、日期范围）
   get_datadog_incident（特定事故的完整详情）
   ```

   如果目标看起来具有防御性，搜索其添加时间附近的事故。如果事故时间线包含“为 X 添加防御性检查”，就是接近直接证据的内容。

<a id="what-good-evidence-looks-like-here"></a>
## 此处的优质证据

- 监控的查询和阈值与代码强制的约束匹配（代码限制为 100，监控在请求超过 100/min 时告警）
- 目标作者创建的仪表盘，其组件对应代码测量或防御的内容
- 指标显示代码合并前生产环境立即出现峰值，之后数值稳定
- 事故记录引用目标代码、相同符号或相同错误字符串
- 日志展示防御性代码应当阻止的具体错误模式，时间戳落在改动前的窗口内

<a id="common-pitfalls"></a>
## 常见陷阱

- **相关不等于因果。** PR 前峰值、之后稳定只是暗示，并非定论，因为同一窗口可能合入其他改动。检查相邻 PR。
- **过度拟合找到的图表。** 图表反映创建者的视角。名为“重试成功率”的图表说明团队关心重试成功，不代表这就是某行代码存在的原因。
- **消失的遥测。** 指标可能重命名、删除或保留期短。如果找不到相关窗口的数据，这是缺口，不是空结果。
- **大规模噪声。** 积极按服务、标签和时间窗口收窄日志搜索。用 `analyze_datadog_logs` 聚合，不要倾倒原始日志。
- **有埋点不等于有因果。** 指标说明有人关心到愿意测量某事，不代表代码是*因为*它而添加的。与提交／PR 日期交叉核对。

<a id="what-to-return"></a>
## 返回内容

对每个相关条目：
- 类型（仪表盘／监控／指标／日志模式／跟踪／事故／笔记本）
- 标题或名称
- 链接或标识符（仪表盘 ID、监控 ID、指标名、事故 ID）
- 负责人／作者和创建／修改日期
- 与问题相关的具体条件、查询或引文（尽可能逐字引用）
- 相关性：对目标代码暗示什么，关联有多强
