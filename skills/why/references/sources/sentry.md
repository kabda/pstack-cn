# Sentry 错误历史

<a id="how-to-search-it"></a>
## 如何搜索

使用 Sentry MCP。

1. **定位。** 如果不知道项目 slug 和组织：

   ```
   find_organizations
   find_projects
   ```

2. **搜索与目标相关的问题。**

   ```
   search_issues（自然语言，例如“PaymentService timeout 中的错误”“uploadFile 中未处理的异常”）
   ```

   根据目标处理的异常类名、函数或类名、检查的错误消息字符串，以及文件路径构建查询。

3. **按发布版本和时间窗口缩小范围。**

   ```
   search_issue_events（按发布版本、时间、环境、trace ID、标签筛选）
   get_issue_tag_values（针对某问题，查看在版本、用户、环境中的分布）
   ```

   对疑似相关问题，检查**首次出现**和**最后出现**（停止是否与目标交付日期一致？）、**受影响发布版本**（哪些版本出现，哪个版本修复？），以及**频率轨迹**（是否先激增再解决？）。

4. **获取完整事件了解上下文。**

   ```
   get_sentry_resource（传入 Sentry URL 或 type+ID）
   ```

   堆栈是否经过目标代码？标签和面包屑记录是否与目标防御的条件匹配？

5. **检查目标附近的发布版本。**

   ```
   find_releases（目标提交日期前后）
   ```

   将发布版本与 PR 合并日期交叉核对。

6. **谨慎使用 Seer。**

   ```
   analyze_issue_with_seer
   ```

   Seer 的 AI 根因分析是生成假设的工具。将其视为推断，而非权威。实际事件和堆栈才是主要证据。

<a id="what-to-return"></a>
## 返回内容

对每个相关问题：
- 问题 ID 和标题
- 项目和组织
- 首次／最后出现时间戳
- 事件数（及已知时的采样率）
- 受影响发布版本
- 展示与目标相关性的代表性堆栈片段（逐字摘录，不是摘要）
- 首次／最后出现与目标交付日期的相关性
- 问题链接
- 任何作者评论或解决说明
