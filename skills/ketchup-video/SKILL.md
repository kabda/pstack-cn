# 视频进展简报

遵循 [`/ketchup`](../ketchup/SKILL.md)，但以简短带字幕视频展示变化，替代其总结和图示。时间窗口从用户在 `/ketchup-video` 之前的最后一条消息开始，而非更早的 `/ketchup`。在仓库外编写并渲染视频，是其只读规则唯一例外。回复包括 ketchup 的开头句、嵌入视频、一行你仍可自行完成的剩余工作，以及待办事项。视频展示决策选项时，使用视频中赋予各选项的名称。如果渲染失败，用一行说明，只给出待决策项。

<a id="slides"></a>

## 幻灯片

使用工作实际产出的截图、录像、diff 和数据，不使用聊天中对它们的描述文字。绘制前，写下用户看完应记住的一句话，并为每张幻灯片写一行。删去不会改变用户认知的幻灯片。最多 10 张，越少越好。这两份笔记都不放进回复。

每张只表达一个观点。围绕同一画面逐张变化，而非切换到无关画面。颜色或形状在各张含义相同。用图像展示工作，例如系统原理、带每个 PR 状态的 PR 堆栈、修复前后对比，或并列选项。用箭头、高亮和动态指明变化。幻灯片绝不是项目列表、状态列表、表格，或彼此没有连接的盒子。

文字尽量少。每个标签放在它所指的对象上，用人会说的平实话，不用“测试：通过”之类标签。绝不给图片已经展示的内容再加说明，也绝不在不同幻灯片之间或下方文字中重复同一事实。

展示用户要求的每件事产生什么结果，是完成、仍在运行、失败，还是未检查。仍待用户的事绝不显示完成。展示过程中发现并修复的缺陷。可见变化没有截图时，在该张说明并写明屏幕上变了什么。仅依据已有事实绘制，绝不虚构数字，绝不画未经捕获的屏幕。

<a id="subtitles"></a>

## 字幕

每张幻灯片一行短字幕，约十个词，只依据该张内容，用你会对用户说的话点明观点。说明图的含义，不要朗读标签。字幕放在幻灯片下方独立条带，每张高度相同，除字幕外留空，绝不遮住画面。字号小，但视频以聊天尺寸播放时仍可读。

<a id="render"></a>

## 渲染

渲染一个无声横向视频，例如 mp4，幻灯片之间有动态过渡。每帧上方是边到边的幻灯片本身，下方是字幕条。直接由幻灯片生成帧，绝不录屏。将字幕烧录进对应幻灯片的各帧，使其在整段停留时间持续显示。停留时间指整张幻灯片完全显示的时长，不包括进入或离开的过渡。每张停留必须足够读完新增词语，至少每三个词一秒。新增词包括字幕和前一张没有的每个词，包括改过的标签。首张所有文字都算新增。截图里的文字不计数。

嵌入视频前检查渲染文件。以聊天尺寸查看每张的一帧，确认字幕可读且不遮挡。把文件中的帧与幻灯片匹配，测量每张实际停留，不用静止帧检测器，因为它会把淡入淡出的微弱尾部也算静止。逐张对比新增词数与实测停留。任何无法在该时长读完的幻灯片都要修复、重渲染、再检查。
