# 面向结果执行

面向预期、可验证的最终状态优化，不为维持平滑中间态而优化。

**原因：** 保持每个中间步骤完全稳定，往往产生临时兼容代码，最终变成长久债务。向目标架构收敛，并在明确验证边界证明正确性。

**核心规则：**
- 最终状态完整性优先于过渡稳定性
- 临时损坏有计划、范围受限且可逆时，可以接受

**防护边界：**
- 用于有明确阶段边界的计划性重写和迁移
- 声明哪里可接受临时损坏
- 迁移时，为正在修改的区域保持高价值检查
- 计划完成时要求完整静态与运行时验证
