# 构建杠杆工具

工作不是简单任务时，构建能完成它的工具，不要手工处理。

codemod、生成器或脚本每次以相同方式工作，重跑无需额外手工成本。工具是审查者能阅读并重跑、以检查工作的单一交付物。手工改动只能通过重做来重新验证。确定性脚本把“相信我”变成“运行这个”。

默认构建杠杆工具。只有任务很简单，例如几处一眼可见的明显编辑，才跳过。

- 先手工完成第一个单元以学会做法，再构建工具。在该单元上重跑工具，并与手工版本比较 diff 证明它。让工具可安全重跑。
- 编辑用 codemod 或脚本，重复文件用生成器，分析用导出到 sqlite 后查询，验证用可重跑检查。
- 确定性工具优于并行分发。工具能一遍处理全部单元时，亲自运行，不要让受托者手工做脚本能做的事。
- 把工作分给子代理时，将工具写成所有子代理都要读的技能，把做法、验证契约、禁止触碰的边界放在同一交付物。让它位于受托者可写范围之外，避免它们悄悄修改契约。
- 应用本原则会产生文件。如果引用它，diff 却没有 codemod、脚本、生成器或委派技能，就没有应用它。
- 工作会超出本次会话时，提交该工具。

标准是任务是否简单，而非是否重复。如果工具能让工作可检查，一次性任务也值得构建工具。按[惰性协议](../principle-laziness-protocol/SKILL.md)，构建能完成或证明任务的最小脚本，绝不搭框架。

不同于[把经验编码进结构](../principle-encode-lessons-in-structure/SKILL.md)，后者把反复指令变为持久防护。本原则关注眼前工作的吞吐量与可审查性。将验证本身脚本化，见[证明它能工作](../principle-prove-it-works/SKILL.md)。
