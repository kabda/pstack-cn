# 测试行为，而非实现

测试是一项关于代码为用户做了什么的主张。用户可以是调用方、终端用户或其他服务。行为是他们通过所用接口能观察到的内容，包括返回值、错误、可回读状态，以及代码外部系统上的效果，例如发送请求、写入一行、发出消息。实现是他们无法观察的内容，例如私有辅助函数、内部调用顺序、中间数据，以及哪个内部协作者完成工作。

用两种假想编辑判断每项测试：

- **破坏行为。** 让代码返回错误值、跳过效果，或执行两次效果。测试仍通过就什么也没证明。常见原因是断言弱于契约、预期值由被测代码计算、重述常量或提示词字符串却从未运行读取它的代码，或断言测试自己构造的数据。
- **改变内部实现。** 保持每个可观察结果不变，重组底层代码。测试因此失败，就说明它绑定实现。每次重构都要重写，却仍抓不到缺陷。

保留能捕捉第一种编辑、又能经受第二种编辑的测试。其他重写或删除。要写出兼具两者的测试，用具体输入通过用户接口驱动代码。从需求而非代码运行结果推导预期值。只断言契约承诺的内容，不多不少。

由契约决定，不由断言形态决定。当承诺是“空购物车绝不扣款”，断言支付客户端没有被调用属于行为。搭配一个确实扣款的用例，让测试表明它能看到调用。模拟外部服务收到的载荷属于行为，因为该服务能观察它；内部辅助函数调用属于实现，因为没有用户看得到。没有匹配记录时，空列表是精确答案；测试只需要某种结果时，它就是空洞检查。精确错误消息会固定没有调用方读取的措辞；调用方用于分支的错误类型才是契约。

测试可固定不变量而非调用，例如某个键必须同时存在于两张表，或编译期类型检查。不变量就是行为。
