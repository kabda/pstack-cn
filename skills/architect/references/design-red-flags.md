<a id="design-red-flags"></a>

# 设计警示信号

综合前筛查每个候选方案。出现警示信号，就有理由修改或否决该结构。

<a id="shallow-module"></a>

## 浅模块

浅模块暴露庞大接口，却没有隐藏多少复杂性。按公共接口背后隐藏的能力与策略相对于接口规模的比例，判断深度。优先选择以简单接口支撑丰富行为的设计。

不要混淆深模块与深调用链。深调用链将理解成本分散到各层；深模块把能力集中在一个接口后面。

留意这些迹象：

- 调用者必须协调多个方法才能完成一次操作。
- 公共选项暴露内部阶段或实现选择。
- 学会接口后，调用者仍必须学会内部实现。

<a id="information-leakage"></a>

## 信息泄漏

信息泄漏让多个模块依赖同一个内部决策。同一种表示、策略或协议细节出现在多处，修改它需要协同编辑。

公共接口重新导出传输类型或线协议类型，就是泄漏。在接口背后把外部数据解析为领域类型。存储 schema、框架对象和协议细节保持私有。

<a id="temporal-decomposition"></a>

## 按时间拆分

按时间拆分是依执行顺序，而非掌握的知识组织模块。将加载、验证、转换和保存分成不同阶段，常使同一表示及其不变量跨多个边界重复。

围绕领域知识和所有权组织代码。不同时间运行的方法，只要保护相同决策，仍可以属于同一个模块。

<a id="pass-through-method"></a>

## 直通方法

直通方法把相同参数转发给形态相同的另一个方法。它增加一层，却未隐藏复杂性。

移除它，或把责任移到能完成操作的模块。只有边界增加了策略、适配或独立抽象时，才保留转发。

<a id="split-ownership"></a>

## 所有权分裂

多个模块写入同一状态，或各自保存副本。编辑某个写入方的智能体看不到其他写入方，规则因而逐渐分歧。

每份状态只有一个所有者。其他模块读取它，或请求所有者修改它。

<a id="two-ways-to-do-one-task"></a>

## 同一任务有两种做法

设计支持多种方式完成同一任务。智能体先找到哪种就照抄哪种，每种做法都会不断增加调用者。

只保留一种做法。在同一次改动中迁移其他做法的调用者，并删除旧做法。

<a id="importable-internals"></a>

## 可导入的内部实现

调用者可以导入模块内部实现。智能体会选择能够编译的最短路径，直接导入内部实现，内部实现因而成为接口的一部分。

使模块外部无法访问内部实现，让来自外部的导入在构建时失败。

<a id="hand-synced-list"></a>

## 人工同步的列表

两处或更多位置列出相同项目，每新增一项就要修改所有列表。只能看到一个列表的智能体只会更新它。

只保留一个列表，其余由它派生。如果无法派生，列表不一致时必须让构建失败。
