# 体验优先

实现便利与用户满意冲突时，选择用户满意。

- 每项功能、控件和选项都必须有理由
- 少交付，交付得更好，三个功能的精致体验胜过十个功能的粗糙体验
- 确定方案前先做原型，设计决策在可丢弃 HTML 中比在生产代码中更便宜
- 做对细节，包括过渡、对齐、间距、反馈、错误状态
- 收紧核心循环，每项功能都应服务中心工作流，否则就别妨碍它

用户是消费这项工作的人。UI 的用户是终端用户；库或内部 API 的用户是导入它的同事；下一位维护代码的工程师也是用户。用相同方式权衡他们的体验，从他们的角度解释影响。

基础应服务体验。基础性思考决定工作的*顺序*，本原则决定*目标*。
