<a id="prove-it-works"></a>

# 证明它能工作

直接检查真实对象，验证每项任务输出。不要从替代指标、自述或“能编译”推断。

**原因：** 未验证工作的正确性未知。间接验证，例如文件修改时间、输出新鲜度、智能体自述、缓存截图，感觉比直接观察便宜。但基于错误推断行动的代价，远高于检查源头。

检查真实对象，不用替代指标：
- 直接检查进程是否存活，不通过派生状态间接判断
- 读取实际值，不读缓存或派生表示
- 验证失败时，先怀疑观察方法，再怀疑系统

<a id="script-the-check-when-you-can"></a>

## 能脚本化就把检查写成脚本

最强证明是能重跑相同比较的确定性脚本，不是一次肉眼查看。编写并运行脚本，保留输出为交付物，让审查者可重跑，无需相信你的话。

让人看得到交付物。只有大型或复杂工作、且轨迹须供日后审计时才提交，例如大型移植或迁移，参见 **show-me-your-work** 技能。
