# 解释数字

- **运行前先写下决策。** 点明什么结果会改变决策，以及噪声下限。多次运行的离散幅度大于效果时停止。
- **问“为什么不能翻倍？”** 点明限制结果的资源或代码路径，例如核心、锁、磁盘、网络，或负载生成器本身。从运行中的 profile 或系统计数器获取，再映射到源码。读代码后的猜测不算限制因素。说不出为什么数字不能好一倍，就不知道自己测了什么。
- **列出数字还可能在测什么，并用证据逐一排除。** 常见嫌疑包括错误、跳过或缓存的工作、根本未运行的代码、未调优的一侧（保留默认设置）、噪声，以及端到端看太小而无关紧要的部分。
- **证据与数字放在一起。** 在说明或链接交付物中放入运行次数、离散幅度和限制因素。

性能数字需用 [benchmark-checklist](../benchmark-checklist/SKILL.md) 技能执行完整流程。评估结果也要对试验提出同样问题：每次运行都做了任务吗，差距跨试验和模型仍成立吗，场景重要吗。

运行开始时没有写下会改变决策的结果，数字背后证据没有运行次数、离散幅度或具名限制因素，或节省时间大于被修改部分原本耗时，都表明跳过了本原则。

不同于检查输出是否真实的[证明它能工作](../principle-prove-it-works/SKILL.md)。
