### 运行时取证

**诊断由你负责。对实时进程插桩，不要只根据源码推测。** 交付物是带证据引用的诊断，不是修复。

1. 通过控制技能，在对应界面捕获实时信号，例如空转进程的 CPU profile、泄漏的堆快照、视觉故障的 CDP trace。要真实产物，不要猜测。
2. 从产物中提炼确凿证据，例如热路径上的函数、泄漏对象到 GC root 的保留链、没有输入仍触发的循环。大型产物交给子代理解析，参见 **guard-the-context-window** 原则技能，主对话保留提炼后的发现。按“子代理”一节选择每个子代理的推理级别及 fast 或标准速度。
3. 相信机制前先证明它。通过 CDP eval 向运行中进程注入插桩，或不重载就热修实时代码，以低成本确认假设。
4. 将发现映射回源码，指出文件、符号，以及分配或调度所在行。
5. 吞吐量检查点保持一行：`throughput checkpoint: n/a, read-only forensics`（吞吐量检查点不适用，本次为只读取证）。

**回复：** 捕获的信号、提炼的发现、如何证明机制、源码位置、产物路径。未被要求则不修复。原因明确后交回 Bug fix（缺陷修复） 或 Perf（性能问题）。
