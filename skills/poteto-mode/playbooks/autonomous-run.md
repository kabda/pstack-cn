### 自主执行

**退出条件由你负责。先定义完成，再持续推进到它成立，不要停下。**

1. 第一次迭代前，把退出条件写成可检查的谓词，例如测试全绿、复现已修复、全部 N 个 PR 已合并、像素差异为零。
2. 用运行环境的 `/loop` 命令选择唤醒机制。它内置于 Cursor 和 Claude Code，不是 pstack 技能；没有时见 SKILL.md 的“运行环境”。有事件可监视，例如 CI、合并、引用前进时，创建监视器子代理，在事件发生时唤醒你，并以较长的定时心跳兜底。没有事件时，采用固定间隔心跳，间隔取决于结果何时值得重查。按“子代理”一节，根据工作选择每个子代理的推理级别及 fast 或标准速度。
3. 每轮只做证据支持的最小改动，用谓词验证；有进展则提交，无帮助则丢弃。只是“也许有用”的多余防护要回退，不能顺带留下。
   按 **sequence-verifiable-units** 原则技能组织顺序，每个单元验证后再做下一个，不要把检查都留到最后。
4. 执行中发现且有助目标的事项由你负责。通过 poteto-mode 亲自处理损坏技能、相关缺陷、不稳定验证器、审查噪声、工具失败、无人接手的后续项和可修复偏移。计划之外的修复放进独立 PR。不要把可逆工作搁置给人，也不要使用 `AskQuestion`。只上报不可逆操作、实验无法解决的真实产品或偏好决策，以及真正的死路。以谓词为主线，每次旁支修复后都回到它。
5. 每轮通过 **show-me-your-work** 技能留下检查点，用一行记录改了什么、谓词是否有所推进。
6. 谓词满足时停止。进入平台期不是停止理由，要继续并调整方法突破。遇到真正死路就上报，不要空转，也绝不放宽谓词来宣布胜利。

**回复：** 退出条件、运行的迭代次数、已落地内容、丢弃内容、谓词最终状态。
