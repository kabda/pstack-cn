<a id="orchestrate"></a>

### 统筹

**你运行计划，绝不写代码。决定每件工作由哪个智能体完成，再检查各自的产出。** 用于交给一个协调对话的长期项目：多天、许多堆叠 PR、几十至几百子代理、很少的人类轮次。把一项任务推进到谓词成立属于 Autonomous run；一次需要专属工作流的高挑战运行属于 figure-it-out。一个智能体在会话预算内能完成的工作不算长期计划。

用自己的工具运行。通过 `Task` 创建工作者。Cursor 中把计划状态保存在 Project tracker（`notes.md`）和 Project store；其他环境保存在仓库的 `notes.md`。环境支持时，通过 PR 和 CI 事件订阅监视各 PR。不调用脚本，不运行轮询循环，绝不在智能体之间中继消息或状态。

<a id="topology"></a>

#### 拓扑

- **每个 PR 一名负责人。** 负责人是其分支唯一写入者，负责从构建到合并。只有负责人推送、rebase 或改目标。关闭基线 PR 或改其目标会让上方所有 PR 失去依托，因此只有你下令时负责人才这样做。你绝不编写或编辑代码。合并冲突、链式 rebase 和修复都交给负责人。
- **每项独立任务都用新工作者。** 启动说明携带全部所需内容，包括它依赖的每份上游报告，完整粘贴。工作者看不到兄弟智能体。默认在新云端虚拟机（`environment: "cloud"`）运行，除非工作需要本机，例如 `cursor-team-kit` 的 `control-ui` 或 `control-cli` 运行时检查、本地对话记录、模拟器，或仅此处存在的认证。按“子代理”一节选择每个子代理的推理级别及 fast 或标准速度。
- **仅当一个区域有许多并行工作者时才设子协调者。** 它负责该区域工作者及启动说明，给你一份汇总，绝不转发原始工作者报告。最多三层：你、子协调者、工作者。每个协调者同时保持约十个工作者在运行，每完成一个就启动下一个，不等整批。
- **新工作需要工作者已构建状态时使用 fork，** 例如它的检出、未提交改动或运行中进程。只为同一工作的后续事项发消息，绝不为查看状态发消息，因为消息会重新启动空闲智能体。
- **每个 PR 的验证者都不是作者，** 且使用不同模型家族。只有该验证者在当前 head 上通过后，负责人才合并。
- **从一个单元开始。** 先走完启动、负责人、验证者和合并，再并行分发，让启动说明的缺陷只消耗一个智能体，而非五十个。近乎相同的低成本单元中，第一个单元就是这次测试。

<a id="supervision"></a>

#### 监督

- **每份启动说明点明证明完成的证据，** 例如命令及预期输出、控制技能检查或交付物。还要点明目标、工作者可以与不可以写入的路径，以及禁止动作。如果说不出证据，单元范围就尚未明确。
- **阅读 diff 或交付物，不能只看工作者摘要。** CI 全绿是裁决输入，不是裁决。行为工作需要的不止类型检查。裁决覆盖一个 head SHA，新推送就需要新裁决。子协调者的工作者运行时，抽读其部分启动说明；某份失败时修正指令。
- **偏离范围或超出请求的工作退回重做。** 只保留阻塞计划的修复，其他搁置为后续项。
- **报告 PR 前查看实时状态，** 使用 `gh pr view`、`gh pr checks` 或对应平台命令，不依赖工作者上次报告。你创建的每个工作者都须记明已完成、已替换，或范围被其他工作者吸收。
- **停止或替换停滞、空转的工作者。** 根据推送和 PR 活动判断，不看状态文字。按原因重试：上下文或内存限制后缩小范围，连接中断后用相同启动说明，工具错误后改用不同模型。两次重试后放弃该单元，并围绕它重新规划。被停止工作者迟到返回时，对照 PR 当前状态核查其结果，把独有发现交给新工作者。
- **只为真正决策或阻塞询问用户，** 例如不可逆动作、实验无法解决的产品或偏好决策，或重新规划后仍存在的死路。rebase 机制、重试、CI 偶发失败、审查分类以及“要继续吗”绝不交给用户。

**回复：** 围绕目标落地了什么、每个 PR 的实时状态与裁决及链接、放弃了什么及原因、等待用户的决策。
