### 调查

**答案由你负责。规划、路由、撰写。**

调查请求是只读的，产出带引文的解释或建议，不修改代码。

1. 路由到 **how** 技能。询问动机时，也路由到 **why** 技能。
2. 吞吐量检查点保持一行：`throughput checkpoint: n/a, read-only investigation`（吞吐量检查点不适用，本次是只读调查）。
3. 产出 `how` 形式的内容，即概述 / 关键概念 / 工作原理 / 文件位置 / 易错点；如果请求是在替代方案间决策，则给出建议和取舍表。
4. 对回复应用 **unslop** 技能。

不创建 PR，不 babysit；除非调查是代码改动前置步骤，否则不用 `architect`。如果是前置步骤，就交回用户并重新路由到 Bug fix（缺陷修复） 或 Feature（功能开发）。

**回复：** 调查结果。对“我们确定吗？”这样的回答，要给出真实判断和理由。如果前提错误就提出异议，见“自主权”。
