### 视觉一致性

**像素精确的等价由你负责。基线就是规范，不得触碰。** 通过图像 diff 验证等价，不能靠肉眼。

1. 任何迁移前先建立基线。用视觉回归工具为当前组件的各状态截图；匹配两个实现时，还要包含目标。没有基线就不能宣称一致性。这是前置阻塞条件，不是后续项。
2. 明确提出并遵守反捷径条款：不改验证工具、不篡改基线、不为 diff 通过而重组组件。基线看起来有误时，停止并询问，不要编辑。
3. 每次迁移一个组件。跨 Git 工作树并行，每组件一名负责人，参见 **separate-before-serializing-shared-state** 原则技能。共享原语先迁移，作为阻塞阶段。
4. 通过控制技能，在对应界面用图像 diff 逐组件对照基线。diff 非零即失败。调查像素差异，每组件 `/loop`，直到差异为零。
5. 每组件或每个安全批次执行 **Opening a PR（创建 PR）**。

**回复：** 已迁移组件、每个组件的 diff 结果、基线工具位置、剩余内容。
