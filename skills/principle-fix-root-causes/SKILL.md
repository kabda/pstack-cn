# 修复根因

调试时修复故障，而非它显露的位置。症状是错误状态变得可见的地方；根因是系统最初做了不该做的事，或未处理应当处理状态的地方。

**原因：** 修补症状会隐藏证据，留下故障让它在别处显露。每次都让系统更难推理，因为代码中多了一个未被点明缺陷的变通处理。

**做法：**
- 先复现。
- 每步都问“为什么”，直到答案是代码中的错误决策，而非更早决策的后果。
- 卡住时插桩。读取实际错误和实际状态，不要猜。
- 询问触发症状的状态是否合理。如果系统可能处于该状态，在该状态下损坏的代码就是根因，在那里处理状态就是修复。如果状态绝不该存在，在损坏点增加检查只会隐藏缺陷。查明是什么产生了该状态。防护、重试、吞掉错误、限制取值和丢弃状态，都是常见的隐藏缺陷方式。
- 只有重启后失败时，先怀疑持久化状态，例如配置文件、缓存、锁文件、序列化状态。
- 检查模式，不只检查个例。找出存在同样故障的每处并全部修复。
- 变通处理需要整段注释辩护时，错的是代码。修复代码，不是注释。
- 关键事实需要深挖才找到时，提出一种低成本、始终开启、能在第一眼就显示它的信号。
