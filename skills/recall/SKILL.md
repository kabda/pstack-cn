# 回顾工作上下文

**开始或恢复工作前，重建用户近期的工作上下文，交回精炼的状态摘要，说明现在进展和下一步。**

保持简洁、紧扣主题。只读范围内各条线索需要的内容，然后停止。

上下文有两类记录。自己的聊天历史记录你做过和决定过什么；共享记录则包含围绕同一代码、以其他名称发生的一切：用户反复报告的症状、已交付又回退的修复、生产环境仍在出现的错误。第二类记录由 **why** 技能跨源码管理、问题跟踪、聊天和问题频道、长篇文档、错误跟踪搜索。长期伴随缺陷的功能，大部分故事都在这里，因此不要仅凭自己的记录重建。

对话记录存放在运行环境指定的位置，每份文件都是 JSONL。找到当前工作区对应目录。不知道是哪种运行环境时，检查以下哪些在此工作区存在：

- **Cursor：**`~/.cursor/projects/<slug>/agent-transcripts/<uuid>/<uuid>.jsonl`。`<slug>` 去掉工作区路径开头的斜杠，再把每个“/”换成“-”（`/Users/you/proj` 变为 `Users-you-proj`）。
- **Claude Code：**`~/.claude/projects/<slug>/<session-id>.jsonl`。`<slug>` 将工作区路径所有非字母数字字符换成“-”（`/Users/you/proj` 变为 `-Users-you-proj`）。
- **Pi：**`~/.pi/agent/sessions/--<slug>--/<timestamp>_<id>.jsonl`。`<slug>` 去掉路径开头斜杠，再把每个“/”换成“-”（`--Users-you-proj--`）。
- **Codex：**`~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`，不按工作区分组。只保留首行 `payload.cwd` 等于工作区路径的文件。
- **OpenCode：**`~/.local/share/opencode/storage/`。会话是 `session/<project-id>/` 下的 JSON 文件，消息位于 `message/` 和 `part/`。

1. 先分类再选择流程。恢复某个特定聊天应使用 `session-pickup` 操作手册，不用本技能。将习惯变为长期技能用 `automate-me`。面向人的工作总结是另一项任务。Recall 在行动前加载近期多个聊天的工作上下文。如果用户已经提供完整状态摘要（路径、分支、改动），直接使用，跳过挖掘。
2. 搜索前锁定范围。固定时间窗口（“近期”必须是实际区间，默认过去 7 天）、指定主题和工作区（默认当前工作区；未获要求绝不读取其他项目的记录）。向用户复述范围。绝不悄悄把“全部”变为“最近 N 个”。
3. 在聊天历史中展开并行。以快速、低成本模型启动并行子代理，每个负责记录集的一部分。要求所有子代理按真实修改时间（`ls -t`）排序候选，绝不按 UUID 名称；先搜索主题，再只读匹配聊天的相关区域；跳过当前聊天和明显噪声（子代理、评测、测试聊天）。每个子代理返回相同结构，每个聊天一块：主题、用户目标、决策、待解线索、困难与纠正、产物（PR、工单、分支），各项引用聊天 UUID。只有一两个聊天时，跳过并行，直接搜索。原始记录留在子代理，主对话只接收发现。根据 **poteto-mode** 技能的“子代理”部分，为每个子代理选择适合任务的推理级别以及快速或标准速度。
4. 主题提到功能、文件、子系统、区域或缺陷时，必须扫描共享记录。这是默认要求，不靠临场判断；“我在 X 上的工作”也不例外。交给 **why** 技能的各来源调查者，但把问题从“为什么这样构建”转为“目前状态是什么、试过什么却没保持住、用户仍在报告什么”。复用它的各来源操作手册，与聊天历史挖掘并行，并继承其原则：每个来源一个调查者，空结果也是发现，不可用的 MCP 跳过并说明。将返回信息纳入简报。只有纯活动回顾且未指定目标（“我这周做了什么”）才能跳过，此时自身历史与实时状态就是完整答案。
5. 核对实时状态。对挖掘和扫描得到的 PR、分支和工单，用 `git`、`gh` 检查。如果答案取决于某智能体实际做过什么（运行的工具、读过的文件、遇到的错误），阅读完整记录，不能只看裁剪的本地副本。
6. 按下方约定写简报。按工作线索分组，紧扣指定主题。

<a id="output-contract"></a>

## 输出约定

先给摘要，再给各条线索状态，然后是问题，最后是下一行动。更深细节放在后面，或删去。

- **摘要。** 最多 5 个列表项，说明工作是什么、整体处于什么状态。
- **线索。** 每条一行，前置且只能使用一个状态标签：`[merged #N]`、`[open PR #N]`、`[in flight <branch>]`、`[verified, uncommitted]`、`[reverted #N]` 或 `[planned, not started]`。分别表示已合并、开放 PR、进行中、已验证未提交、已回退、已计划未开始。没有标签的线索就还没写完，补上标签。
- **问题。** 最多 5 项，关注反复出现的问题。包括用户持续报告的症状，以及已交付又回退的修复，让下次尝试从上次失败处开始。
- **下一行动。** 只给最有用的一个具体行动。

相关功能或工单除非阻塞本项，否则不纳入。摘要与线索超出一屏时，先删细节，不先删线索。用 **unslop** 技能处理简报；聊天发现用 UUID 引用，共享记录用来源引用（PR 编号、工单 ID、聊天永久链接、错误跟踪问题）。公开输出前净化隐私上下文。

**回复：**遵循上述约定的简报。
